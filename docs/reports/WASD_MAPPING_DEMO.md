## 實作邏輯流程

```
1. 檢測按鍵狀態
   ┌─────────────────┐
   │ W 鍵按下? y -= 1│
   │ S 鍵按下? y += 1│
   │ A 鍵按下? x -= 1│
   │ D 鍵按下? x += 1│
   └─────────────────┘
           ↓
2. 判斷是否有輸入
   ┌─────────────────┐
   │ x ≠ 0 或 y ≠ 0? │
   └─────────────────┘
      ↓YES        ↓NO
      ↓           ↓
3a. 正規化      3b. 零向量
   ┌──────────┐  ┌──────────┐
   │normalize()│  │set(0, 0) │
   └──────────┘  └──────────┘
           ↓
4. 返回方向向量
   ┌─────────────────┐
   │getMovementInput()│
   └─────────────────┘
```

## 正規化數學

### 公式

```
給定向量 v = (x, y)

長度 = √(x² + y²)

正規化向量 = (x/長度, y/長度)
```

### 範例計算

#### 單鍵 W

```
原始: (0, -1)
長度: √(0² + (-1)²) = √1 = 1
正規化: (0/1, -1/1) = (0, -1)
結果長度: 1.0 ✅
```

#### 對角線 W+D

```
原始: (1, -1)
長度: √(1² + (-1)²) = √2 ≈ 1.414
正規化: (1/1.414, -1/1.414) = (0.707, -0.707)
結果長度: √(0.707² + 0.707²) = √0.999 ≈ 1.0 ✅
```

#### 無輸入

```
原始: (0, 0)
不進行正規化，直接返回 (0, 0)
結果長度: 0.0 ✅
```

## 為什麼需要正規化？

### 問題：未正規化的對角線移動

```
單鍵移動速度: 1.0 單位/幀
對角線移動速度: √2 ≈ 1.414 單位/幀  ❌ 太快！
```

### 解決：正規化後的對角線移動

```
單鍵移動速度: 1.0 單位/幀
對角線移動速度: 1.0 單位/幀  ✅ 一致！
```

## 遊戲中的應用

```typescript
// 在 PlayerCharacter 中使用
update(delta: number): void {
  const input = this.inputController.getMovement();
  
  // input 保證是正規化的向量（長度 0 或 1）
  const velocity = input.clone().scale(this.moveSpeed);
  
  this.sprite.x += velocity.x * delta;
  this.sprite.y += velocity.y * delta;
}
```

### 移動速度一致性

假設 `moveSpeed = 100` 像素/秒：

- **W 鍵**: 向量 (0, -1) × 100 = 每秒向上移動 100 像素
- **W+D 鍵**: 向量 (0.707, -0.707) × 100 = 每秒向右上移動 100 像素

**所有方向的移動速度都相同！** ✅

## 程式碼追蹤範例

### 場景 1: 按下 W 鍵

```typescript
// 初始狀態
x = 0, y = 0

// update() 被呼叫
if (this.keys.W.isDown) y -= 1;  // y = -1
// x = 0, y = -1

if (x !== 0 || y !== 0) {  // true
  this.direction.set(0, -1).normalize();
  // 長度 = 1, 不需改變
  // direction = (0, -1)
}

// getMovementInput() 返回 (0, -1)
```

### 場景 2: 按下 W+D 鍵

```typescript
// 初始狀態
x = 0, y = 0

// update() 被呼叫
if (this.keys.W.isDown) y -= 1;  // y = -1
if (this.keys.D.isDown) x += 1;  // x = 1
// x = 1, y = -1

if (x !== 0 || y !== 0) {  // true
  this.direction.set(1, -1).normalize();
  // 長度 = √2 ≈ 1.414
  // 正規化: (1/1.414, -1/1.414)
  // direction = (0.707, -0.707)
}

// getMovementInput() 返回 (0.707, -0.707)
```

### 場景 3: 無按鍵

```typescript
// 初始狀態
x = 0, y = 0

// update() 被呼叫
// 沒有按鍵被按下
// x = 0, y = 0

if (x !== 0 || y !== 0) {  // false
  // 不執行
} else {
  this.direction.set(0, 0);
  // direction = (0, 0)
}

// getMovementInput() 返回 (0, 0)
```

## 效能分析

### 每幀運算成本

```
1. 4 次布林檢查 (W, A, S, D)
2. 最多 4 次整數加法
3. 1 次條件判斷
4. 1 次向量設置
5. 0-1 次正規化運算（僅在有輸入時）
```

### 正規化運算成本

```typescript
normalize() {
  const len = Math.sqrt(this.x * this.x + this.y * this.y);
  if (len > 0) {
    this.x /= len;
    this.y /= len;
  }
}
```

- 2 次乘法
- 1 次加法
- 1 次平方根
- 2 次除法

**總計**: 非常輕量，對 60 FPS 遊戲無影響

## 與觸控搖桿的等價性

KeyboardMouseAdapter 和 TouchInputAdapter 都實作 IInputAdapter 介面，提供相同的正規化向量：

```typescript
interface IInputAdapter {
  getMovementInput(): Phaser.Math.Vector2;  // 保證長度 0 或 1
}
```

這確保了：
- 鍵盤玩家和觸控玩家有相同的移動速度
- 遊戲邏輯不需要知道輸入來源
- 可以在運行時切換輸入方式
